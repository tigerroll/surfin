# Surfin Batch Framework: アーキテクチャ設計戦略

## 1. 概要
Surfin Batch Frameworkは、大規模なデータ処理を効率的かつ信頼性高く実行するために設計されたGo言語ベースのバッチ処理フレームワークです。本フレームワークは、JSR-352（Java Batch）の概念をGo言語の特性に合わせて再構築し、モジュール性、拡張性、および堅牢なトランザクション管理を提供します。

## 2. 設計原則
*   **疎結合なコンポーネント:** `fx` (Uber Fx) を活用した依存性注入により、各コンポーネント（Reader, Processor, Writer, Partitioner等）を疎結合に保ち、テスト容易性と交換可能性を確保します。
*   **宣言的なジョブ定義:** JSL (Job Specification Language) を採用し、YAML形式でジョブのフロー、ステップ、依存関係を定義します。これにより、コードを変更することなくジョブの構成を変更可能です。
*   **堅牢なトランザクション管理:** `tx.Tx` インターフェースを通じた抽象化により、データベースの種類に依存しない一貫したトランザクション制御（REQUIRED, REQUIRES_NEW, NESTED等）を実現します。
*   **スケーラビリティ:** `PartitionStep` を通じて、単一のジョブを複数のパーティションに分割し、並列実行する仕組みを提供します。また、`RemoteStepExecutor` により、リモート環境へのジョブ委譲もサポートします。

## 3. 主要コンポーネント

### 3.1. ジョブ実行エンジン
*   **JobRunner:** ジョブのライフサイクル全体を管理し、フロー定義に基づいてステップを順次または並列に実行します。
*   **StepExecutor:** ステップの実行戦略（ローカル実行 vs リモート実行）を抽象化します。

### 3.2. ステップタイプ
*   **ChunkStep:** 大規模データ処理向け。Reader, Processor, Writerを組み合わせ、チャンク単位でのコミットとチェックポイント管理を行います。
*   **TaskletStep:** 単一の処理単位。複雑なロジックや、チャンク処理に適さない単発のタスクを実行します。
*   **PartitionStep:** 処理を分割し、並列実行するためのコントローラー。

### 3.3. データアクセスと状態管理
*   **Repository:**
    *   `JobRepository` を通じて、ジョブインスタンス、実行履歴、ステップの状態、チェックポイントデータを永続化します。
*   **ExecutionContext:**
    *   ジョブやステップ間で状態を共有するためのキーバリューストア。
    *   再開（Restart）時の状態復元に利用されます。
*   **ItemStream:**
    *   状態を持つバッチコンポーネントのライフサイクルを定義します。
    *   `Open` で状態を復元し、`Update` でチェックポイント状態を更新し、`Close` でリソースを解放します。

### 3.4. 拡張機能
*   **ExpressionResolver:** JSL内の動的な式（例: `#{jobParameters['key']}`）を解決し、実行時に値を注入します。
*   **SecretResolver:** URIスキーム（`file://`, `env://`）に基づき、機密情報を安全に解決・注入します。
*   **Metrics & Tracing:** OpenTelemetryを統合し、ジョブの実行時間、エラー、処理件数などを可視化します。

## 4. トランザクションとエラーハンドリング
*   **トランザクション伝播:** `SimpleStepExecutor` は、ステップの定義に基づいてトランザクションの開始、参加、中断、ネスト（セーブポイント）を自動的に制御します。
*   **スキップとリトライ:** `SkipPolicy` および `RetryPolicy` により、特定のエラーに対する柔軟な対応が可能です。チャンク処理中のエラー発生時には、チャンク分割（Chunk Splitting）による部分的なスキップもサポートしています。

## 5. 今後の拡張方針
*   **分散実行の強化:** リモート実行エンジンとの連携を強化し、より大規模なクラスタ環境での実行をサポートします。
*   **メタデータストアの多様化:** 現在のSQLベースのRepositoryに加え、NoSQLやクラウドネイティブなメタデータストアへの対応を検討します。
*   **JSLの機能拡張:** より複雑な条件分岐や、動的なフロー制御を可能にするためのJSL構文の拡張を行います。
